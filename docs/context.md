# 上下文压缩

压缩策略参考 [Kode-CLI 固定版本](https://github.com/shareAI-lab/Kode-CLI/tree/400bbf0449707846465895ef64cfbbd18bea4763/packages/core/src/utils)，接入主 Agent、子 Agent 共用的 `ContextCompactor`。

## 模型窗口与估算

在本地 `.env` 设置 `MODEL_CONTEXT_TOKENS`，填写实际 API 服务支持的上下文窗口。未配置时采用参考项目相同的 200,000 Token 回退值，不能把该值当作已核实的模型规格。错误配置会降低压缩时机的准确性；更换模型时也要核对窗口。

字符约按 4 个字符估算为 1 Token，再为消息开销乘以 4/3；图片按每块 2,000 Token 估算。该算法参考 Kode，不是精确 tokenizer，对不同语言可能存在误差。系统提示词、记忆和工具定义不逐项计入消息估算，而使用窗口预留空间。统计面板继续显示接口实际返回的 usage。

有效窗口 = 模型窗口 − min(模型窗口的 10%, 20,000)。

- 旧结果转存检查阈值：有效窗口 − 33,000。
- 自动摘要阈值：有效窗口 − 13,000。
- 阈值下界沿用参考项目的正数/零保护，不是累计 Token 或请求次数限制。

## 执行顺序

1. 工具返回时，单个结果超过 400,000 字符就保存全文，仅将引用与 2,000 字符预览加入 `messages`。请求前也检查刚交付的结果，兼容恢复会话和后台结果。
2. 每次模型请求前，接近窗口才考虑转存旧工具结果。文件读取、搜索、列文件、编辑、写入、Shell 工具参与；任务、Skill、子 Agent 结论、MCP 工具结果不参与这层旧结果清理。
3. 已转存的结果不重复处理。其余结果按调用顺序选择，保护最近 3 次有结果的符合条件调用；尽量将未转存正文降到约 40,000 Token。预计回收不足 20,000 Token 时不执行。转存后保留 400 字符预览和完整结果引用，不调用模型。
4. 转存后若仍达到自动摘要阈值，且至少有 3 条消息，调用当前模型生成摘要。完整历史先归档；摘要输入保留中间证据，使用结构化工具调用数据，不再截取前 20,000 与后 60,000 字符。
5. 摘要提示中补充最多 50 个任务的状态和依赖、已调用技能、MCP 工具信息。保留当前用户请求、末尾待处理消息；末尾是工具结果时，连同对应的 assistant 工具调用保留，避免孤立的 `tool_result`。
6. 成功摘要后恢复最多 5 个近期成功读取过的项目内文件，保持原行范围。恢复继续受 `read_file` 每次最多 1,000 行、约 20,000 字符的限制。项目外文件、拒绝/失败的读取、数据库归档不自动重读。恢复内容标记为参考数据。

自动摘要失败或返回空文本时，保留压缩前消息，不用空摘要替换历史。手动 `compact` 失败会向上报告错误。原有请求过长补救流程继续保留，每次连续错误最多补救重试一次；成功模型请求会重置该重试计数。

## 存储与适配

`STORAGE_BACKEND=mysql`：全文位于 `artifacts.content`，消息中的引用为 `artifact://编号`，模型可通过 `read_file` 分页找回。文件模式继续使用本地归档。旧文件路径和旧纯引用标记仍可读取；历史数据不会因升级自动重建。

本项目沿用现有 Python、模型客户端、权限和用量统计。摘要使用当前模型；没有引入 Kode 的模型指针管理或完整文件新鲜度服务。自动恢复文件沿用本项目已有读取限制，范围小于参考项目每文件 10,000、总计 50,000 Token 的预算。项目目前没有独立 Plan 文件模块，因此以已有任务系统提供状态快照。

原来的消息条数裁剪和按 50,000 字符触发的旧结果/强制预览压缩已移除。这次没有增加累计 Token、模型请求次数或任务轮数限制，也没有加入通用重复调用拦截。

## 验证

`tests/test_context_policy.py` 检查窗口阈值、不提前清理正文、旧结果预览和收益条件；`tests/test_context_compactor.py` 检查摘要证据、错误保留、任务/技能/MCP 状态与文件恢复；`tests/test_compact_loop.py` 检查主子循环真实协议往返及原有错误重试。MySQL 分页找回和微压缩由隔离数据库集成测试覆盖。测试使用模拟模型，不请求付费 API。
