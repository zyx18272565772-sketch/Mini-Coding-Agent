# 跨会话记忆

参考 [s09 的完整 code.py](https://github.com/shareAI-lab/learn-claude-code/blob/main/s09_memory/code.py)，实现存储、召回、提取和整理。与主工具、子智能体、任务系统、权限、技能及上下文压缩共用主循环。

## 存储与范围

`memory/store.py` 的 `FileMemoryStore` 只负责读写，不依赖模型客户端。每条记忆对应项目工作目录下 `.memory/*.md`，文件头包含 `name`、`description` 和 `type`，正文保存具体信息；写入后重建 `.memory/MEMORY.md` 索引。当前不依赖 MySQL 或 Redis，后续可替换存储实现并迁移已有数据。

四种类型为 `user`（用户偏好）、`feedback`（持续适用的反馈）、`project`（稳定项目事实）、`reference`（参考资料或查找线索）。这些分类都受项目目录范围约束，同项目会话共享，不跨项目自动传播。桌面工作进程使用会话的工作目录，而不是启动应用时的目录。

模型提出的候选必须包含 `scope`；仅保存 `persistent`，过滤 `current_task`、临时措辞、缺失或无效字段、重名、相同简介及相同正文。`scope` 用于写入前判断，不作为新的工具或权限类型。过滤属于规则检查，仍可能存在语义误判，记忆不保证完整准确。

## 运行流程

1. 主循环开始时，读取记忆目录，以入口传入的原始用户请求选择最多五条相关记录。没有记忆时不产生选择请求。选择请求或 JSON 解析失败时，改用名称和简介的关键词匹配；中文同时匹配相邻汉字。
2. 加载所选正文，合计预算为 20,000 字符；简短目录最多 12,000 字符。它们加入本轮系统提示词，工具循环复用。记忆是背景数据，当前用户请求优先；记忆不会作为新消息追加到 `messages`。
3. 模型不再请求工具，且 `Stop` 钩子允许结束后，提取长期信息。输入包含单独保留的当前原始请求，以及最近十二条消息中的文字（最多保留末尾 8,000 字符）；不直接提取工具参数和工具结果。提取请求明确禁止保存助手猜测、临时进度或对话摘要。
4. 新增记忆后检查整理条件。记录达到十条时，让模型合并重复、应用明确纠正、清理过期信息。单次整理输入超过 20,000 字符则跳过；新列表必须整体有效，包含一至三十条，不能重名或为空。

选择、提取、整理使用现有配置中的同一个模型，分别以 200、1,000、3,000 tokens 限制输出，因此会增加模型请求。没有新记忆时不整理；普通工具执行轮次不会反复召回或提取。记忆处理出现普通异常时显示中文提示并跳过，已生成的主回答保留。

子智能体仍保持独立消息，不独立提取或写入长期记忆；主智能体在委派提示中提供必要背景。这样不会把内部探索文字直接当成用户偏好保存。

## 并发与失败处理

文件写入使用同目录临时文件替换；写入与读取用操作系统文件锁协调同一项目的多个进程。调用模型期间不占用锁。整理前记录快照，提交时再次比较；如果另一会话已修改记录，就取消本次替换，保留新数据。替换抛出异常时尝试恢复原快照和索引。

这仍是文件存储：多个文件的更新不是数据库事务，进程被强制终止时不保证整批更新原子完成。文件损坏或路径越出项目时保留原文件，跳过本轮处理。`.memory/` 已加入本项目 `.gitignore`，不会作为代码提交。

## 与其它存储的区别

- `.agent_data/sessions/` 保存桌面会话消息和界面事件，用于继续原会话；`.tasks/` 保存项目任务、状态和依赖。
- `.transcripts/` 和 `.task_outputs/` 保存压缩归档与大型工具输出，用于按需找回历史细节。
- `.memory/` 保存选择性的长期信息，用于新会话理解偏好和项目背景，不替代前两者。

终端显示 `[记忆]` 日志，桌面版以 `notice` 事件显示检索、召回、提取、保存、整理及失败提示。它们属于界面进度，不混入模型的消息历史。关闭后新建同项目会话即可使用已有记忆；换到其它项目会使用该项目自己的 `.memory/`。

自动化验证使用临时目录、模拟模型和 SDK 模拟网络，覆盖跨会话、桌面重启后的召回、原始请求在压缩后的保留、临时信息过滤、异常回滚、并行进程写入和整理冲突；不调用真实 DeepSeek API。
