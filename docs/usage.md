# 模型用量统计

## 统计范围

`llm/generation.py` 是模型请求的统一入口。主、子 Agent 的工作请求、记忆选择/提取/整理、上下文摘要都经过它，分别归为 `main`、`subagent`、`memory`、`compact`。`llm/usage.py` 用 `ContextVar` 绑定当前用户任务；同步子 Agent 复用同一个统计对象。后台 shell 命令不调用模型，不计入模型请求数。

一次应用层 SDK 调用开始前增加请求数，响应结束后读取接口实际返回的 `usage`，不靠字符数推算。Anthropic 的 `input_tokens` 表示未缓存输入，缓存读取和写入另列；总 Token 为输入、输出、缓存读、缓存写之和。缓存 Token 仍计入总量，但这里不换算金额。不同服务的缓存价格不同。

缺少输入/输出统计、网络异常或流式中断会增加 `unknown_calls`。若流中已收到部分 usage，保留已知值并标记不完整；桌面中显示“已知”说明这些数字只是下限。正在等待响应的请求通过 `pending_calls` 表示。强制停止或重启桌面时，未完成请求改为用量不完整，不显示为完整的零消耗。SDK 内部自动重试不能从现有结果可靠分拆，应用层只记一次；请求失败同样计入请求次数。

这里只新增计数、用途和状态，不保存新的提示词、密钥或模型推理正文。原有会话保存机制继续保存模型上下文及界面记录。

## 任务与恢复

每次用户发送新任务创建新的 `run_id`，主、子和辅助请求共享统计。累计 Token 和请求次数不参与执行控制，不提供 80% 用量警告，也不限制子 Agent 的累计工作轮数。单次 API 请求的最大输出参数、工具参数完整性检查及上下文压缩继续按原逻辑工作，它们不属于累计用量额度。

连接、超时等可恢复错误支持手动“继续执行”，沿用同一个任务编号与累计用量，不重复加入用户消息，不自动重放已完成工具。恢复的是主会话检查点；子任务的局部消息不保存为可独立恢复的子会话。原有停止按钮及权限确认继续有效。

桌面将各任务的最新用量记录保存在原会话 JSON 的 `usage_runs`，当前任务为 `usage`；会话累计按任务编号汇总，不把多次快照或续跑重复相加。旧会话可读取，统计启用前的请求没有 usage，无法准确补算。

旧用量记录里的 `limits`、`warning` 不再参与执行控制，恢复后的新快照只包含统计。旧状态 `limited` 在桌面启动时迁移为可继续的停止记录，原任务计数保持不变。旧环境变量 `AGENT_MAX_MODEL_CALLS`、`AGENT_MAX_TOTAL_TOKENS` 不再读取。命令行同样只统计用量；退出后内存消息和计数不持久保存。

## 界面展示

输入框上方显示本次任务与会话累计用量。展开可查看四种用途的输入、输出、请求数和缓存读写。面板不显示额度档位、上限、用量警告或加额按钮，也不向模型添加统计文本。

工具调用按用户轮次合并为默认折叠的执行记录，保留调用数、运行中状态与异常数量。第一次展开查看工具列表，第二次展开查看具体参数和结果；子 Agent 的过程也在同一组内。模型主回复继续直接显示。刷新或切换回会话默认收起，审批面板始终在折叠组外。
