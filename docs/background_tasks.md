# 后台命令执行

参考 [s11 完整 code.py](https://github.com/shareAI-lab/learn-claude-code/blob/main/s11_background_tasks/code.py)，在已有 bash 工具中增加 `run_in_background`，工具数量不变。

## 使用方式

向 Agent 描述：“请在后台运行项目测试，同时检查 README，收到测试结果后报告结论。”

模型决定命令是否适合独立执行，工具调用示意：

```json
{"name": "bash", "input": {"command": "python -m unittest discover", "run_in_background": true}}
```

省略参数或传入 `false` 时同步执行。`true` 时先在当前 Agent 线程执行原有权限检查，允许后才启动后台线程，立即返回真实生成的 `bg_...` 编号和“已启动，尚未完成”。启动确认不能作为命令成功、任务验证通过或任务依赖完成的依据。

## 执行流程

1. `agent_loop()` 为本轮请求创建独立的 `BackgroundManager`；子 Agent 也创建自己的管理器和消息列表。
2. `execute_tool()` 触发 `PreToolUse`，通过后将显式要求后台执行的 bash 调用交给管理器。
3. 后台线程调用 `run_bash_process()`；完成后在锁内保存输出、退出码、状态，并通知条件变量。线程不调用模型、不触发权限输入，也不修改 `messages` 或桌面通信管道。
4. 每次请求模型前，当前 Agent 线程收集已完成结果，用 `<task_notification>` 文本加入自己的 `messages`。原始调用 ID 只收到一次启动确认 `tool_result`，不会重复补交第二次工具结果。
5. 模型暂时停止调用工具但仍有后台任务时，本轮保持运行：有现成结果就直接继续，否则等待线程完成事件。等待不调用模型、不消耗模型 Token。收到结果后，主循环自动再次请求模型，无需用户补发消息。
6. 所有后台结果都已交付，且模型没有继续调用工具时，才触发 `Stop`、提取主会话记忆并结束。本轮等待状态不是任务完成。

完成结果上限与普通 bash 一致为 50,000 字符，消息仍经过现有上下文压缩流程。退出码非零、超时或执行器异常会交付失败状态，供模型判断和修复。

与参考示例的区别：主循环会主动等待未交付的后台结果，保证本轮内自动继续；`PostToolUse` 在实际完成结果被收集时运行一次，启动确认不触发完成钩子。主、子 Agent 的结果各自进入独立上下文，只有主 Agent 保存主会话检查点。

## 桌面与命令行

桌面仍使用每轮独立工作进程，后台命令未交付前不发送 `done`、不退出进程。工具卡片显示“后台运行中”，实际完成后更新为“已返回”或“执行失败”，展开可查看编号、退出码和输出。等待期间可以使用停止按钮，权限需要确认时沿用原有弹窗。

命令行通过 `main.py` 使用相同主循环，输出后台启动、等待和完成提示，收到全部结果后打印最终回复。Ctrl+C 会中断本轮并清理该轮启动的命令。

## 生命周期

- 后台命令继续使用 120 秒超时，适合测试、构建等有限时长命令；不用于长期运行的服务。
- 同步与后台共用命令执行器，超时或取消会清理命令进程。Windows 使用 `taskkill /T /F`，Unix 使用独立命令进程组；这些操作只针对本次启动的进程。
- 发生模型错误、Ctrl+C 时，退出管理器会取消尚未完成的命令；桌面停止会终止本轮工作进程及其命令子进程。
- 后台运行状态位于当前进程内存中，不属于 s10 的 `.tasks` 任务记录。正常完成的通知随桌面 `messages` 检查点和执行事件保存；关闭程序后不会恢复尚未完成的命令，也不会自动重新执行。
- 等待和线程本身不收费；后台结果交付后的模型请求、已有的记忆与摘要请求仍按原逻辑消耗 Token。

## 验证

后台管理器测试覆盖即时返回、结果只交付一次、多个任务独立完成、目录隔离、线程失败、命令失败、超时和取消。循环测试覆盖权限先于启动、等待不反复请求模型、自动继续、真实完成钩子、模型异常清理，以及子 Agent 独立接收结果。桌面测试使用真实工作进程、真实系统命令和模拟 SDK 网络，覆盖恢复上下文、权限拒绝、子 Agent 结果隔离和停止命令子进程。
