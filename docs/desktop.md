# 桌面版第一版

采用 React + Vite 编写界面，pywebview 创建窗口并提供 Python 通信接口。继续共用原有 Agent，保留命令行入口。

## 功能和验收

- 左侧按项目分组显示会话；项目可展开、收起，每个项目可以创建多个独立会话；重启后恢复项目、聊天和模型上下文。
- 点击“项目”旁的加号，通过系统文件夹选择器创建项目，名称取文件夹名；重复选择同一目录复用已有项目。创建项目后进入该项目的新会话。
- 项目和会话的“…”菜单提供重命名；保存后重启仍保留，手动会话名不被第一条消息覆盖。重命名不改磁盘目录或模型上下文。
- 左下角“设置”提供浅色、深色主题及 12–22px 字号，立即保存并在重启后恢复；新外观默认浅色、15px。设置面板支持 Escape 关闭。
- 中间展示用户消息、模型回复和输入框；Enter 发送，Shift+Enter 换行，中文输入法选词不发送。
- 输入框“＋”菜单提供添加文件、添加文件夹，显示可移除的引用卡片；文件支持多选，文件夹单选。重复选择去重，草稿与引用按会话隔离。
- 主、子智能体的回复逐段显示在同一条消息中，完成后保留 Markdown 格式；停止或断线时保留已经显示的部分文字，并标注中断。
- 每轮工具与子智能体过程默认折叠成一条执行记录；标题实时显示调用数和运行状态，展开后逐项查看名称、参数和结果。
- 输入区只统计本次任务及会话累计模型用量，不设置请求或 Token 额度、不显示用量警告；审批面板不随工具记录折叠。
- bash 支持后台执行，工具卡片区分启动确认和实际完成；没有其他工作时显示等待，命令完成后自动继续处理，不需要再发消息。
- 输入区上方提供可展开的项目任务，显示进度、依赖和领取者；同项目的会话共享 `.tasks` 中的任务。
- 复用原有三道权限检查。需要用户审批时在界面显示原因和参数，允许或拒绝后才继续；硬拒绝仍不可放行。
- 展示运行、等待确认、完成、停止、出错状态。停止会终止本次后台任务及命令子进程，不会自动重试已执行的操作。
- 模型连接失败、超时、临时服务错误或断流时显示“继续执行”，手动继续原任务，保留已完成的工具结果、已显示文字和累计用量；刷新或重启后仍可继续。
- 每个会话可通过系统文件夹选择器指定工作目录；执行期间不能更改该会话目录。
- 项目、会话行末菜单可删除，确认后才执行；运行中禁止删除，删除项目包含其聊天记录，保留项目源文件。
- 输入框显示后端实际配置的模型标识。选中聊天文字后可点击“回复”加入引用；右键显示 `Copy` / `Select all`。Markdown 表格、代码高亮及复制按钮与两种主题同步显示。

## 界面约定

参考 Codex 的项目与会话层级、侧栏底部设置入口、居中阅读区、底部输入区和折叠执行记录，使用本项目名称和中文内容。默认白色聊天背景、浅灰侧栏，可切换深色；全局颜色和字号变量同时调整聊天、工具、权限与设置面板。代码使用独立高亮资源块，Markdown 支持 GFM 表格。窄窗口可折叠侧栏，正文、菜单和代码块不超出窗口。交互约定见 [desktop-appearance.md](desktop-appearance.md)。

## Python 与前端接口

通过 `window.pywebview.api` 调用以下方法，统一返回 `{ok: true, data: ...}` 或 `{ok: false, error: "中文说明"}`：

| 方法 | 参数 | 作用 |
| --- | --- | --- |
| bootstrap | 无 | 项目、会话摘要、主题/字号设置、公开模型标识、默认目录和数据读取提示 |
| create_project | 无 | 选择文件夹并登记项目；取消返回 null，同目录返回已有项目 |
| create_session | 可选 project_id | 在指定项目新建会话；省略则使用默认目录项目 |
| rename_project | project_id, name | 修改项目显示名称，1–80 个字符，不改源目录 |
| rename_session | session_id, name | 修改会话标题并标记为手动名称，不改模型消息 |
| pick_attachments | session_id, kind | kind 为 file/folder，打开系统选择器并返回 kind/name/path 引用数组；取消返回空数组 |
| set_theme | theme | 保存 dark 或 light，返回主题设置 |
| set_font_size | font_size | 保存 12–22 的整数字号，返回外观设置 |
| delete_session | session_id | 删除不在运行中的会话记录，返回 deleted_session_ids |
| delete_project | project_id | 删除项目及其会话记录，返回 deleted_session_ids/deleted_project_id；保留源目录 |
| get_session | session_id | 载入聊天、执行记录、待确认操作、项目 tasks 快照与 task_error、usage/usage_total、model |
| choose_workspace | session_id | 更改当前会话目录，并将此会话移入对应项目；其他会话保持原目录 |
| send_message | session_id, text | 启动后台任务，拒绝同一会话重复启动 |
| retry_run | session_id | 从检查点手动继续可恢复的失败任务，沿用原任务编号和累计计数，不新增用户消息 |
| poll | session_id, after | 获取增量事件、最新状态、项目 tasks/task_error、usage/usage_total、failure；快照独立于聊天游标 |
| resolve_permission | session_id, request_id, allow | 回答当前权限请求，旧请求不能放行新操作 |
| stop | session_id | 停止当前任务 |

事件按会话递增编号，包含 `user`、`assistant`、`tool_start`、`tool_result`、`permission`、`permission_resolved`、`state`、`error`、`notice`。工具和模型事件携带 `scope`，区分主智能体和子智能体。`notice` 用于记忆等运行提示，以文字展示，不加入模型消息。

`usage` 事件携带共享任务的完整用量快照，包含 `run_id`、`by_purpose`、状态和累计计数；桌面按任务编号替换最新记录，汇总为 `usage_total`，避免续跑时重复累计。用量不参与执行控制。旧状态 `limited` 在启动时迁移为可手动继续的错误状态，旧统计仍保留。统计含义与恢复边界见 [usage.md](usage.md)。

后台启动的 `tool_result` 另带 `background: true` 和 `task_id`，表示命令仍在运行；完成使用 `background_result`，携带原 `call_id`、`task_id`、`status`、`exit_code` 和实际 `output`，更新原工具卡片。该完成事件同时对应一条交给模型的通知文本，不再补第二条同 ID 的 `tool_result`。完整行为见 [background_tasks.md](background_tasks.md)。

流式回复另外使用 `assistant_start`、`assistant_delta` 和 `assistant_end`。同一回复共享 `message_id`，再按 `scope` 区分主、子智能体：开始事件创建消息，片段事件追加文字，带同一编号的 `assistant` 用完整正文替换片段并结束输出状态；异常使用 `assistant_end` 标记中断。旧会话没有编号的 `assistant` 仍按整段回复显示。

## 执行和保存

本节的 JSON、`.tasks` 和 `.memory` 路径描述对应默认文件模式。启用 MySQL 后，界面接口保持一致，项目、会话、运行、事件、用量、任务和记忆写入数据库；外观设置保存在本机 `appearance.json`，大型归档仍在本地。项目移除使用隐藏状态，保留项目任务和记忆。配置与旧数据迁移见 [mysql.md](mysql.md)。

每轮运行使用独立后台进程，按会话设置工作目录和任务领取者身份。项目任务通过 `.tasks` 文件共享，不复制到会话检查点。原 Agent 通过默认关闭的事件接口报告进度；命令行继续使用终端权限输入。后台进程与窗口进程通过管道通信，界面短轮询增量事件。

进程启动参数只包含管道和入口信息，完整模型历史在 `worker_ready` 握手后由后台接收线程传输，传输期间不持有桌面服务的全局锁。点击发送立即显示带“正在发送”标记的临时消息；后端确认后显示正式消息，失败则移除临时消息并保留草稿和引用。临时消息不进入模型上下文或持久化记录。空轮询复用已有事件数组，内容未变化的 Markdown 回复不重复解析和高亮。测量条件与回归方法见 [desktop-performance.md](desktop-performance.md)。

接收事件失败时显示通信错误；保存检查点或时间线失败时显示存储错误。接收线程异常结束后清理所属工作进程；即使磁盘持续不可写，也释放运行状态并在当前窗口保留可轮询的错误信息。此时尚未成功保存的内容不能保证在重启后恢复。工作进程发现管道断开后停止执行，不重复发送用量和失败通知。MCP 会话关闭时保留原始 Agent 异常，模型超时等错误仍按原分类处理。

桌面工作进程显式开启流式模式，主、子循环通过 `llm/generation.py` 使用 SDK 的 `messages.stream()` 接收 SSE；首段文字立即上报，其余片段以约 80 毫秒或 256 字符合并上报。运行中的界面每 150 毫秒轮询一次，非运行状态使用 500 毫秒。完整消息接收结束前不执行工具，不把半截工具调用写入模型检查点；输出达到上限且包含工具调用时同样停止执行。记忆处理和上下文摘要仍使用独立请求，不显示其内部输出。

开始和片段事件先保存在内存供轮询，完整回复、检查点、停止或失败时写入会话文件，避免每个片段都重写整个文件。正常停止后恢复会话可看到部分文字；进程崩溃前尚未持久化的片段可能丢失。部分正文只用于界面，不作为完整的模型回复续传。命令行保持原来的整段输出方式。

会话保存在项目的 `.agent_data/sessions/`，使用独立 JSON 文件和原子替换。模型上下文与界面时间线分别保存，因此上下文压缩不会删除屏幕上的历史。仅在完整工具批次或最终回答后保存模型检查点，停止时不会留下缺少工具结果的调用。已经发生的文件修改不会撤销。崩溃时正在执行的会话下次启动显示为已停止，损坏的数据文件保留并提示。

失败信息 `failure` 包含 `kind`、中文 `message` 与 `retryable`。模型请求因连接、超时、HTTP 429/408/409/5xx 或缺少完整流结束事件而失败时，主循环先保存合法消息检查点，再报告可恢复错误。后台命令在退出时清理，其完成或取消通知一并保存。认证、请求配置、存储及进程异常不提供此按钮，避免从不确定的执行位置重放操作；更改工作目录后也不能续跑旧目录中的失败任务。

`retry_run` 不追加用户任务，也不自动执行旧工具调用；它把已保存的工具结果重新交给模型，由模型决定下一步。模型仍可能主动请求同一个操作，该新调用照常经过权限检查。部分流式文字保留在界面，不作为完整响应加入模型上下文。继续沿用原 `run_id` 和用量。重复失败时需要再次手动继续，不增加应用层自动重试循环。

`desktop_app/catalog.py` 将项目目录和主题保存在同一数据目录下的 `workspace.json`。会话增加 `project_id`，按项目继承工作目录，消息单独保存，任务按项目共享。旧会话启动时按原来的工作目录归组，保留原编号、模型消息和界面记录；旧 todos 字段只保留历史，不恢复旧工具。项目配置损坏时，先备份原文件，再从会话目录恢复项目。任务行为见 [task_system.md](task_system.md)。

外观设置同时保存 `font_size` 和 `appearance_version`。升级新外观时首次设为浅色，后续保留用户主题。模型标识来自环境变量或应用 `.env` 中的 `MODEL_ID`，读取显示信息不初始化模型客户端。删除只按已登记的项目/会话编号操作；会话文件路径严格限制为数据目录中的编号 JSON，项目目录不参与删除。全部项目已删除时，不会通过默认目录自动重新登记。

引用由前端作为单独卡片编辑，发送时序列化为带“仅供参考”和“当前请求”标签的用户文本，与当前指令一起传入已有 Agent。历史显示时恢复引用卡片。未发送的引用只在当前窗口内存保留，按会话编号隔离；关闭窗口后不恢复未发送草稿。右键全选范围限制在聊天列表，不包含输入框。剪贴板优先使用浏览器接口，WebView2 不允许该接口时回退为复制命令。

本地文件与文件夹引用也按会话保留在前端草稿中；发送时在用户消息末尾附加带“仅供参考、按需使用工具读取”说明的 JSON 路径数组，历史界面解析为文件卡片。选择器只校验所选路径存在及类型，不读取文件正文、不复制文件、不遍历目录，也不改变会话工作目录。模型使用原有 read_file、glob、bash 等工具读取，所有调用仍经过既有权限流程。已发送的引用随用户消息保存；未发送的引用在关闭窗口后清空。选择文件并不增加图片、PDF 或 Office 文件的专用解析能力。

重命名接口使用原编号保存，拒绝空名称、超过 80 字符的名称及控制字符。项目名更新到侧栏、顶部、欢迎页和输入区，磁盘路径仍通过提示显示；会话保存 title_custom，避免首次发送时被自动标题覆盖。保存失败恢复内存中的旧名称。运行中的任务也可以修改显示名称。

长期记忆保存在所选项目目录下的 `.memory/`，同项目的不同会话及任务进程共享，换项目则隔离。主循环处理请求前召回相关记忆，结束时提取；处理期间任务仍显示运行中。记忆更新使用文件锁和整理快照检查，详细规则见 [memory.md](memory.md)。

## 验证要求

保留并通过已有 unittest；覆盖项目内多会话、旧会话归组、主题恢复、保存恢复、会话隔离、权限等待和拒绝、停止命令进程、事件及检查点。前端构建通过，并在真实浏览器检查项目折叠、主题切换、设置面板、草稿保留、聊天、工具、审批、停止和窄窗口；真实 WebView2 验证桥接和设置保存。模拟模型验证不调用真实 DeepSeek API。

`tests/desktop_usage_ui.cjs` 配合模拟界面服务验证默认折叠、工具详情、超过 60 次请求仍可完成、纯用量显示、刷新恢复和审批可见；`tests/test_usage.py`、`tests/test_usage_loop.py`、`tests/test_desktop_usage.py` 验证共享统计、大量 Token 不触发停止及旧环境变量失效。

`tests/test_desktop_appearance.py` 验证外观恢复、公开模型名、删除边界和源文件保留；`tests/desktop_appearance_ui.cjs` 验证代码/回复复制、右键菜单、选中引用、跨会话隔离、主题字号、删除确认及空状态。所有操作使用临时会话数据。

`tests/test_desktop_retry.py` 使用真实 SDK 与模拟网络验证失败继续、重启恢复、工具不重放、未知用量保留、断流和旧额度停止记录迁移；`tests/desktop_retry_ui.cjs` 检查按钮、草稿保留、重复失败、认证错误及深色窄窗口。真实 WebView2 验收也覆盖该按钮。

`tests/test_desktop_composer.py` 验证重命名恢复、手动标题、名称边界、保存失败回滚及文件选择；`tests/desktop_composer_ui.cjs` 验证加号菜单、引用去重/移除/会话隔离、发送恢复、重命名、键盘及主题窄窗口。`tests/desktop_native_smoke.py` 同时验证真实桌面桥接下的文件引用和重命名操作；文件选择器及模型使用模拟数据。
