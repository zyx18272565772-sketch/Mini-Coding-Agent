# 用量统计、执行额度与折叠执行记录

用户已授权：按每次任务共享额度，默认 30 次模型请求 / 200,000 Token；简单 10 / 50,000，复杂 60 / 500,000。80% 提醒，到达上限停止新请求，可增加额度继续。所有模型用途都统计，前端记录默认折叠。

## 实现顺序

1. 统一模型请求的 usage 统计，按主 Agent、子 Agent、记忆、压缩分类；流式与普通路径各记一次，缺失用量标注未知。
2. 主、子 Agent 共用任务额度；额度异常不被辅助模块吞掉。完整工具结果与检查点保持配对。
3. 桌面保存每个 run 的最新累计快照，按 run ID 去重汇总；支持三档额度及显式增加额度续跑。
4. 前端显示本次与会话累计消耗，分类明细；每轮工具与子 Agent 过程汇总为默认折叠的执行记录。
5. 模拟 API 测试、前端测试、构建和真实浏览器验收；更新文档。

## 边界

- Token 按 API usage 事后核算，是停止下一次请求的阈值，不是精确的金额预算；最后一次请求可能超出阈值。
- SDK 内部网络重试不等于应用请求计数；断流或未返回 usage 时只展示已知下界。
- 不读取/修改真实 .env，不调用付费模型，不改变项目任务和记忆的存储位置。
- 不增加依赖；当前目录没有 Git 仓库，不初始化 Git。

## 验收

- 普通、流式、子 Agent、记忆、压缩都计数，续跑不重置历史消耗，新任务重新计数。
- 任一上限达到后，不再发模型请求，界面显示额度耗尽而非完成。
- 保存、重启、切换会话后统计不串台、不重复累加。
- 折叠状态仍显示执行中、错误和调用数量，权限审批保持可见；可键盘展开查看完整工具参数与结果。
