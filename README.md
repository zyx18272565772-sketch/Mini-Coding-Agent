# Mini Coding Agent

一个使用 Python 开发的本地编程智能体，提供 React + pywebview 中文桌面界面和交互式命令行入口。模型通过工具搜索代码、读取文件、生成和修改代码、运行命令与测试，并根据执行结果继续处理任务。

项目参考逐步实现 Agent Loop、权限、钩子、子智能体、技能、上下文压缩、记忆、任务系统和后台命令，并增加桌面会话管理、流式显示、失败继续、用量统计和文件工具优化。目前主 Agent 有 **15 个工具**，子 Agent 共享其中 **8 个基础工具**。

## 已实现的功能

| 模块 | 当前能力 |
| --- | --- |
| Agent Loop | 模型请求 → 工具执行 → 结果回传 → 再次请求模型，直到本轮结束 |
| 文件操作 | 内容搜索、带行号分页读取、唯一匹配编辑、文件写入与路径查找 |
| 命令执行 | 同步或后台运行 Shell 命令，支持超时、取消和退出码反馈 |
| 权限与钩子 | 硬拒绝、规则匹配、逐次审批，以及执行前后和停止事件 |
| 子智能体 | 独立上下文执行明确子任务，共享工作目录，只向主 Agent 返回最终文本 |
| 技能加载 | 启动提供技能目录，按需加载完整 `SKILL.md`，内置中文代码审查技能 |
| 上下文管理 | 工具结果转存、历史裁剪、旧结果压缩、模型摘要和请求超长补救 |
| 跨会话记忆 | 按项目保存长期偏好和事实，在新请求中选择性召回 |
| 项目任务 | 持久化任务、依赖检查、领取和完成，已替换 `todo_write` |
| 桌面交互 | 项目与多会话、流式回复、折叠执行记录、权限确认、停止与失败后继续 |
| 用量统计 | 请求次数、输入输出和缓存 Token，按主 Agent、子 Agent、记忆、压缩分类 |

任务拆分、工具选择和失败后的修复方案由模型决定，程序负责执行工具及检查参数、权限和任务状态。工具链支持“修改代码 → 运行测试 → 读取失败信息 → 继续修改”，实际任务效果取决于模型、提示词和项目环境。

## 配置与启动

### 环境与模型配置

- 当前主要验证环境为 Windows、Python 3.12，Windows 桌面版需要 WebView2 Runtime。
- 前端使用 React + Vite，Node.js 需满足当前 Vite 的要求：`^20.19.0 || >=22.12.0`。
- 模型服务需要兼容 **Anthropic Messages API**。当前使用 Anthropic Python SDK，只有 OpenAI Chat Completions 协议的接口不能直接接入。

在项目根目录创建 `.env`，字段参考 [.env.example](.env.example)：

```dotenv
ANTHROPIC_API_KEY=你的接口密钥
MODEL_ID=服务支持的模型名称
# 使用兼容服务时填写其 Anthropic Messages 接口地址
# ANTHROPIC_BASE_URL=https://your-provider.example
```

也可以通过同名环境变量配置。使用 DeepSeek 或其他模型服务时，应确认服务提供的接口协议和模型标识与当前客户端匹配。密钥由 Python 后端读取，不返回前端，不应提交到代码仓库。

### 桌面版

在项目根目录的 PowerShell 中准备环境。已有虚拟环境或 `.env` 时跳过对应创建步骤，保留已有配置。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
Copy-Item .env.example .env
```

填写 `.env` 后，安装前端依赖并构建：

```powershell
Set-Location frontend
npm ci
npm run build
Set-Location ..
.\.venv\Scripts\python.exe desktop.py
```

已有虚拟环境、模型配置和前端构建时，直接运行 `desktop.py`。普通启动加载 `frontend/dist/`，不需要单独启动前端服务；修改前端源码后需要重新构建。

开发前端时，在 `frontend/` 中运行 `npm run dev`，另一个终端从项目根目录运行 `.\.venv\Scripts\python.exe desktop.py --dev`。该模式连接本机 Vite 开发服务器，普通使用无需开启。

### 命令行

只使用命令行时，安装 `requirements.txt`，配置 `.env` 后运行 `main.py`，不需要桌面依赖和前端构建。它与桌面版共用 Agent Loop、工具、记忆和任务，但回复以整段文字输出。

输入 `q`、`quit`、`exit` 或在等待输入时按 Ctrl+C 退出；任务执行期间 Ctrl+C 会中断本轮并退出。工作目录是启动时的当前目录。聊天消息只保存在当前进程内存中，退出后不会恢复；项目记忆、任务和压缩归档仍保存在磁盘。

## 桌面使用

- **项目与会话**：侧栏“项目”旁的加号选择文件夹，项目内可创建多个会话。项目和会话支持重命名、删除；重命名只改变显示名称，删除项目会删除其会话记录，保留源代码、记忆和任务文件。运行中的项目或会话不能删除。
- **聊天与执行过程**：Enter 发送，Shift+Enter 换行，中文输入法选词不发送。主、子 Agent 的文字流式显示，支持 Markdown、代码高亮和复制。每轮工具和子任务过程默认折叠为“执行记录”，展开后查看具体工具的参数和结果。
- **权限与控制**：需要审批时，输入区上方显示原因和参数，允许或拒绝只针对本次调用。停止会终止本轮工作进程及命令子进程，已发生的文件修改不会撤销。
- **失败后继续**：连接中断、超时、临时服务错误或断流时，可以手动点击“继续执行”，从已保存的主会话检查点继续，并沿用原任务用量。认证、配置或存储错误需要先排查原因。
- **文件和文字引用**：输入框“＋”可添加文件或文件夹路径，发送时仅提供路径，由 Agent 按需读取。选中聊天文字可点击“回复”引用；右键提供 `Copy` / `Select all`。未发送草稿和引用按会话隔离，只保留在当前窗口内存中。
- **设置与任务**：支持浅色、深色主题和 12–22px 字号，默认浅色、15px，设置在重启后保留。项目任务面板展示状态、依赖和领取者，输入框显示实际配置的模型名称。

每轮桌面任务在独立的 Python 工作进程中执行，通过管道与窗口进程通信；前端通过 pywebview 接口提交请求和轮询增量事件。模型上下文与界面时间线分开保存，因此上下文压缩不会删除已显示的历史。

继续执行不会自动重放旧工具，但模型收到历史后仍可能提出新的同类调用，新调用照常检查权限。子 Agent 的局部消息不保存为可独立恢复的子会话。详见 [桌面设计](docs/desktop.md)、[外观与交互](docs/desktop-appearance.md)。

## Agent 的运行流程

1. 入口接收用户输入，加入 `messages`，并单独传入当前请求 `active_request`。
2. 主 Agent 按当前请求召回项目记忆，加入本轮系统提示词；工具循环复用这份记忆背景。
3. 请求模型前整理上下文；桌面模式接收流式响应，完整工具参数接收完成后才执行工具。
4. 保存模型回复并提取 `tool_use`，通过共用执行器依次检查权限、触发钩子，按工具名调用处理函数。
5. 用原调用 ID 对应的 `tool_result` 回传结果，再次请求模型。主动压缩在完整工具批次处理后生效。
6. 后台命令完成后以独立通知交付结果。如果模型暂时不再调用工具，后台任务仍未交付，循环会等待完成事件并自动继续；等待本身不请求模型。
7. 没有继续的工具调用和后台结果时，触发 `Stop`。钩子允许结束后，主 Agent 尝试提取、保存及整理长期记忆，然后返回最终回复。

`messages` 是入口与主循环共用的列表，压缩通过切片赋值原地更新。模型回复和工具结果会进入后续请求，但屏幕上的全部历史不一定原样发送，较早内容可能已被裁剪、转存或摘要。

### 子智能体、技能与任务

`task(prompt)` 同步启动子 Agent，使用独立消息列表和系统提示词。委派说明应包含目标、必要背景和期望结果；中间工具结果留在子上下文，父对话只接收最终文本。两者共享工作目录、模型配置和当前用户任务的用量；子 Agent 不继续委派，也不直接操作项目任务工具。

技能代码位于 `skill/`，技能文件位于 `skills/<名称>/SKILL.md`。启动扫描保存名称、简介和全文，系统提示先提供目录，模型通过 `load_skill` 加载具体要求，再使用普通工具执行。新增或修改技能后需重新启动；桌面工作进程从 Agent 根目录加载技能，文件操作则使用会话选择的项目目录。

任务状态为 `pending → in_progress → completed`。模型先创建任务并拿到真实 ID，再建立依赖、领取、实际执行和验证，最后标记完成。程序拒绝循环依赖及未满足依赖的领取，完成记录本身不证明测试通过。主 Agent 可以亲自执行或委派；当前不提供任务取消、删除和重新分配工具。详见 [任务系统](docs/task_system.md)。

## 工具列表

主 Agent 使用全部 15 个工具，标记“共用”的 8 个工具也提供给子 Agent。

| 工具 | 范围 | 主要参数及行为 |
| --- | --- | --- |
| `bash` | 共用 | `command`，可选 `run_in_background`；同步或后台执行命令 |
| `search_files` | 共用 | `query`，可选 `path`、`file_glob`、`max_results`、`case_sensitive`；返回路径、行号和匹配片段 |
| `read_file` | 共用 | `path`，可选 `start_line`、`end_line` 或 `limit`；带行号分页读取 |
| `write_file` | 共用 | `path`、`content`；创建或覆盖文件，必要时创建父目录 |
| `edit_file` | 共用 | `path`、`old_text`、`new_text`，可选 `replace_all`；默认要求唯一匹配 |
| `glob` | 共用 | `pattern`；按路径通配符查找，最多显示 200 项 |
| `load_skill` | 共用 | `name`；按注册名称读取完整技能说明 |
| `compact` | 共用 | 无参数；请求在本批工具完成后压缩历史 |
| `task` | 主 Agent | `prompt`；同步委派子任务，接收最终文本 |
| `create_task` | 主 Agent | `subject`，可选 `description`；创建项目任务 |
| `update_task` | 主 Agent | `task_id`、`addBlockedBy`；为尚未领取的任务增加依赖 |
| `list_tasks` | 主 Agent | 无参数；查看项目任务列表 |
| `get_task` | 主 Agent | `task_id`；读取完整任务记录 |
| `claim_task` | 主 Agent | `task_id`；领取依赖已满足的任务 |
| `complete_task` | 主 Agent | `task_id`；完成当前会话领取的任务，报告新解锁任务 |

文件操作推荐顺序：**搜索定位 → 读取相关行 → 精确修改 → 读取或运行测试验证**。

- `search_files` 使用 Python 标准库，不依赖额外程序。默认区分大小写，跳过常见依赖、构建、Agent 数据目录和 `.env` 文件，不隐式跟随链接；当前使用固定忽略项，未解析 `.gitignore`。只搜索不超过 1,000,000 字节的 UTF-8 文件，默认最多 30 个匹配行，并限制扫描时间、文件数和输出长度。提示跳过或搜索未完成时，不能据此认定整个项目没有匹配。
- `read_file` 行号从 1 开始，包含结束行；`limit` 与 `end_line` 不能同时指定。默认读取 200 行，最多 1000 行及约 20,000 字符，达到限制时提示后续读取位置。超长行会单独标记截断。
- `edit_file` 拒绝空原文、零处或多处匹配。多处匹配时应增加上下文，确需全部替换才指定 `replace_all=true`。保留 UTF-8 BOM 和纯 CRLF 文件换行；展示行号和搜索结果的路径前缀不属于源码。
- `bash` 在 Windows 上通过 `cmd.exe` 执行，工具名称保留为 `bash`。单条命令超时 120 秒，输出最多保留 50,000 字符。后台模式适合测试、构建等有限时长的独立工作，不用于常驻服务，启动确认不代表执行成功。

工具定义与处理函数映射集中在 `tool/registry.py`，主、子循环共用 `tool/executor.py`。详见 [文件工具](docs/file_tools.md)、[后台命令](docs/background_tasks.md)。

## 权限与事件钩子

工具执行前先处理 Shell 硬拒绝名单，再匹配项目外文件访问等规则，需要时逐次审批。终端只有输入 `y` 或 `yes` 才允许，空输入或输入结束默认拒绝；桌面通过确认面板处理。未命中规则的普通操作自动执行。

| 事件 | 触发位置 | 默认回调 |
| --- | --- | --- |
| `UserPromptSubmit` | 收到新用户任务后 | 打印当前工作目录 |
| `PreToolUse` | 每个工具执行前 | 权限检查、调用日志 |
| `PostToolUse` | 工具返回后；后台命令为实际结果交付时 | 大输出提醒 |
| `Stop` | 没有继续的工具调用或后台结果，准备结束时 | 统计当前保留的工具结果 |

默认回调在首次导入 `hook` 包时注册。`trigger_hooks()` 按顺序调用，返回非 `None` 会提前结束本次事件；`PreToolUse` 返回内容可阻止当前工具，`Stop` 返回非空提示可要求继续。停止统计读取当前上下文，不代表整个会话的累计调用数。

工作目录是文件工具的默认路径范围，**不是操作系统沙箱**。Shell 仍使用当前用户权限，字符串与正则规则不能覆盖任意命令行为。工作区外的专用文件工具访问需要审批，直接调用底层 `run_*` 函数不经过 Agent 权限钩子。

## 上下文、记忆与本地数据

主、子 Agent 各自管理上下文。`ContextCompactor.prepare()` 在工作模型请求前按顺序检查：

| 阶段 | 条件 | 处理 |
| --- | --- | --- |
| 批量结果预算 | 最新一批工具结果合计超过 200,000 字符 | 优先转存较大的结果，保留预览和路径 |
| 历史裁剪 | `messages` 超过 50 条 | 归档历史、保留部分首尾消息，保护工具调用与结果配对 |
| 旧结果压缩 | 估算上下文超过 50,000 字符 | 转存较早的大结果，优先保留近期结果 |
| 模型摘要 | 进一步转存后仍超过字符阈值 | 调用模型生成目标、进度和剩余工作的摘要 |

前三阶段不额外请求模型，生成摘要会增加请求。主动调用 `compact` 也会请求摘要；接口报请求过长时会尝试归档、摘要并重试一次。摘要保留当前用户请求并标记背景内容；字符阈值不是模型实际 Token 上限，也不是累计用量限制。

长期记忆与聊天记录分开。主 Agent 在每次用户请求开始时选择相关记忆，本轮结束时提取稳定信息，达到条件时整理；子 Agent 不独立写入长期记忆。记忆由模型提出、规则过滤，不保证完整准确。详见 [记忆模块](docs/memory.md)。

| 数据 | 保存位置 | 范围 |
| --- | --- | --- |
| 桌面会话、模型检查点、用量 | Agent 根目录 `.agent_data/sessions/<会话ID>.json` | 各会话独立 |
| 项目列表、主题与字号 | Agent 根目录 `.agent_data/sessions/workspace.json` | 桌面配置 |
| 长期记忆与索引 | 所选项目 `.memory/` | 同项目会话共享 |
| 任务状态与依赖 | 所选项目 `.tasks/` | 同项目会话共享 |
| 压缩会话归档 | 所选项目 `.transcripts/` | 按需找回历史 |
| 转存工具结果 | 所选项目 `.task_outputs/tool-results/` | 按需读取全文 |

操作其他项目时，记忆和任务目录会出现在那个项目里。数据目录按需创建；后台运行中的命令状态只保留在内存，关闭后不恢复或自动重新运行。

### 用量统计

统计接口实际返回的输入、输出、缓存读写 Token 和应用层请求次数，不换算金额。主 Agent、子 Agent、记忆和压缩请求都计入同一用户任务，失败后继续沿用原 `run_id`，会话累计按任务汇总。

不设置累计 Token、累计请求次数或子 Agent 轮数上限，也没有额度档位和 80% 用量警告。单次模型输出参数、工具输出限制、命令超时和上下文压缩继续生效。SDK 内部重试不单独增加应用层请求数；缺少完整 usage 时显示已知值和不完整标记，统计前的历史无法准确补算。详见 [用量统计](docs/usage.md)。

## 测试与验证

Python 使用标准库 `unittest`，前端使用 Node.js 测试运行器。核心测试使用临时目录、模拟模型或 SDK 模拟网络，不消耗真实模型 API 用量；部分测试会启动本地命令和工作进程。

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py"
Set-Location frontend
npm test
npm run build
```

最近一次文件工具优化后的验证：**262 项 Python 测试中 261 项通过，1 项因 Windows 符号链接权限跳过；19 项前端测试通过，生产构建成功。** 覆盖主/子循环消息往返、文件工具、权限钩子、任务依赖、压缩、记忆、后台命令、流式输出、会话恢复和用量统计。

浏览器验收使用 Playwright、`tests/desktop_browser_server.py` 和对应的 `tests/desktop_*_ui.cjs`；`PLAYWRIGHT_MODULE` 可指定已有 Playwright 安装位置。文件工具卡片由 `tests/desktop_file_tools_ui.cjs` 验证中文名称、关键词、默认折叠和结果展开；`tests/desktop_native_smoke.py` 用于真实 Windows WebView2 验证，需要相应本机运行环境。

这些测试验证程序机制，不等于真实模型在任意代码仓库上的任务成功率。当前没有代码覆盖率百分比或真实任务基准成绩。

## 当前限制与参考来源

- 当前定位为本地桌面编程 Agent 原型，尚未提供完整 OS 沙箱、容器隔离或工作树隔离。
- `edit_file` 已有匹配校验，仍整份读写，尚无版本冲突检查、原子替换和自动撤销；`write_file` 默认覆盖已有内容。
- Git 操作可以通过 Shell 执行，尚无专用 Git 工具；未集成 MCP、Agent Teams、workflow 或 goal 等后续模块。
- 任务状态由模型更新；命令失败可反馈模型继续处理，但没有确定性的测试验收门，也没有所有错误通用的自动重试流程。
- 会话、任务和记忆使用本地文件，尚未使用 MySQL 或 Redis；关闭程序不会恢复仍在执行的命令。

Agent Loop、工具映射、权限/钩子、子上下文、技能加载、上下文压缩、文件记忆、依赖任务和后台通知等核心思路参考 learn-claude-code 的相关章节。教程各章是机制示例，本项目在同一主循环中组合实现，`todo_write` 已由任务系统替换。

本项目的工程扩展包括 React + pywebview 桌面界面、项目与会话管理、独立工作进程和增量事件、真实流式显示、主会话检查点与失败继续、共享用量统计、文件锁与数据保护，以及内容搜索、分页读取和编辑匹配校验。各模块细节及与参考实现的区别见上述专题文档。
