# Python 编程智能体

当前实现智能体主循环、权限检查、事件与钩子、子智能体委派、技能加载、[s08 上下文压缩](https://github.com/shareAI-lab/learn-claude-code/blob/main/s08_context_compact/code.py)、[s09 跨会话记忆](https://github.com/shareAI-lab/learn-claude-code/blob/main/s09_memory/code.py)、[s10 任务系统](https://github.com/shareAI-lab/learn-claude-code/blob/main/s10_task_system/code.py)，以及 React + pywebview 中文桌面界面。主智能体拥有十四个工具，子智能体拥有七个共用工具。

## 桌面版

桌面入口是 `desktop.py`，命令行入口仍为 `main.py`，两者共用原来的 Agent。界面按 Codex 的项目/会话侧栏、居中聊天和底部输入区组织，默认白色背景、浅灰侧栏，也支持深色。桌面版包含聊天、工具详情、权限确认、任务停止与工作目录选择。每轮对话的工具及子智能体过程合并为默认折叠的“执行记录”，展开后逐个查看参数和结果；标题显示运行状态和异常数量，权限确认直接显示在输入区上方。

桌面版的主、子智能体回复采用真实模型流式输出，生成的文字逐段显示在同一条消息中，最终正文支持 Markdown。停止或连接中断时保留已显示的部分文字；工具调用必须等完整响应接收后才执行。命令行仍保持整段输出。流式只改变传输与显示方式，模型任务流程和计费 token 不会因此自动减少。

模型连接失败、超时、服务临时错误或断流后，输入区上方会显示“继续执行”。点击后从已保存的上下文继续原任务，保留已完成的工具结果、文件修改和累计用量；不会自动重放先前的工具调用，也不重复添加用户任务。未完整接收的工具参数不执行。重新打开桌面程序后仍可继续这类失败任务；认证或配置错误需要先修正配置。

侧栏按“项目 → 会话”组织。点击“项目”旁的加号选择本地文件夹，创建项目；项目名默认取文件夹名，同一文件夹不会重复登记。每个项目旁的加号创建该项目的新会话，顶部“新建会话”在当前项目中创建。项目可折叠，旧会话会自动按原工作目录归组。更改某个会话的工作目录，会把该会话移到对应的项目，不会更改其他会话的目录。

左下角“设置”可选择深色、浅色主题，并调节 12–22px 字号，默认 15px。切换立即生效，草稿和引用保留，重新打开仍使用已保存设置。新外观首次启用浅色，后续遵循用户选择。项目及外观偏好保存在 `.agent_data/sessions/workspace.json`，会话记录各自独立保存。

项目及会话行末的“…”菜单提供删除。删除项目会同时删除它的会话记录，确认弹窗会说明数量；所选项目目录、源代码、记忆和任务文件均保留。运行中不能删除。删除当前会话后切换到剩余会话，删除全部项目后显示空状态，被删除的项目不会在重启时自动恢复。

项目和会话的“…”菜单也提供“重命名”，名称为 1–80 个字符，保存后重启仍有效；只改显示名称，不改项目目录或会话编号。手动会话名不会被第一条消息覆盖。输入框左下角的“＋”菜单可添加文件或文件夹引用，引用显示为可移除卡片，按会话隔离。发送时只把路径交给 Agent，通过已有工具按需读取，不自动展开目录或发送文件全文；读取项目外路径仍经过原来的权限检查。工作目录继续通过侧栏底部入口切换。

输入框显示实际配置的 `MODEL_ID`，不向前端返回密钥。聊天回复支持 Markdown 表格、列表、代码高亮和代码/回复复制。选中文字后松开左键，点击“回复”可引用到输入框，发送前可以移除；引用和草稿按会话隔离。聊天区域右键提供 `Copy` / `Select all`，全选只作用于聊天内容。具体交互见 [docs/desktop-appearance.md](docs/desktop-appearance.md)。

首次安装桌面依赖 `requirements-desktop.txt`，在 `frontend` 中安装 npm 依赖并构建界面，然后用项目虚拟环境运行 `desktop.py`。本项目已构建的情况下，只需启动桌面入口。Windows 使用 WebView2 Runtime，模型继续读取原来的 `.env` / 环境变量，不在前端保存密钥。

React 源码在 `frontend/src/`，生产构建输出到 `frontend/dist/`。开发界面时可以运行 Vite，并使用 `desktop.py --dev` 连接本机 5173 端口；普通启动读取构建文件，不需要单独启动前端服务器。

输入框上方只显示本次任务与会话累计用量，展开可查看主 Agent、子 Agent、记忆处理、上下文压缩各自的请求次数、输入、输出、缓存读写 Token。统计不设置累计 Token 或请求次数上限，不提供额度档位、80% 警告或增加额度按钮。新任务独立统计，会话累计继续保存；失败后继续沿用原任务编号和累计用量。旧版因额度停止的会话在启动时提供继续入口。

用量根据接口实际返回的 usage 统计，不换算金额。输入历史重复发送也会重复计入，SDK 内部重试不单独增加应用层请求次数。接口未返回完整用量或输出中断时标记为“用量不完整”，已知 Token 只是下限；统计启用前的历史不补算。设计与边界见 [docs/usage.md](docs/usage.md)。

每个会话的完整界面记录和模型上下文保存在 `.agent_data/sessions/`，关闭后再次启动可以继续会话。屏幕上的工具记录不会因为模型上下文压缩而消失。每轮运行使用独立的后台进程，按会话设置工作目录；项目任务保存在所选项目的 `.tasks/`，同项目的多个会话共享。输入区上方的“项目任务”可展开查看状态、依赖和领取者。运行中不能更改该会话的目录；可以切换查看其他会话。

权限沿用现有三道检查。需要用户审批时，任务暂停在窗口中的确认面板；选择只对本次调用有效。硬拒绝没有允许按钮。停止会结束当前后台进程及其命令子进程，已发生的文件修改不会撤销。关闭窗口也会停止任务；再次启动不会自动重跑中断的工具。模型上下文在完整工具批次和最终回复处保存检查点，避免留下缺少结果的工具调用。

桌面接口和验收约定见 `docs/desktop.md`。Python 测试使用 unittest，前端状态测试使用 `frontend` 中的 `npm test`；`tests/desktop_native_smoke.py` 在真实 Windows WebView2 中验证通信、审批和主题设置，`tests/desktop_browser_server.py` 配合 `tests/desktop_ui.cjs`、`tests/desktop_projects_ui.cjs` 使用临时会话和模拟模型验收界面，不会调用真实 API。浏览器验收脚本使用 Playwright，可从 `PLAYWRIGHT_MODULE` 指定其安装位置。

`agent/agentloop.py` 从 `llm/client.py` 导入模型客户端，从 `tool/registry.py` 导入主智能体的工具定义和处理函数映射。基础文件与命令工具不依赖智能体或模型客户端；`task` 在实际执行时再加载 `agent/subagent.py`，让工具注册过程不必读取模型配置，并避免循环导入。

系统提示词集中在 `agent/prompts.py`。提示词、工具说明、权限确认、钩子日志及工具状态提示使用中文，模型默认用中文回答。工具名、接口字段、事件名和配置变量保留原标识；文件内容、命令输出以及底层异常信息保留原文。

`main.py` 负责读取终端输入、保存会话历史、调用主循环并打印最终回答。空行会忽略；输入 `q`、`quit`、`exit` 或在等待输入时按 Ctrl+C 退出。任务执行期间按 Ctrl+C 会中断任务并退出。命令行同样只统计用量，不设置累计请求或 Token 额度。命令行退出后不保存该内存会话。

`main.py` 在接收用户输入时，将 `query` 作为独立的 `active_request` 传给 `agent_loop(messages, active_request)`。主循环先召回相关记忆，然后循环执行：整理上下文 → 调用模型 → 保存回复 → 执行整批工具 → 回传结果 → 如有请求则压缩历史 → 继续循环。

没有工具调用时先触发 `Stop`，允许结束后再提取长期记忆；新增记忆达到整理条件时尝试整理，然后返回。当前保留的消息仍在传入的 `messages` 中；压缩通过 `messages[:] = ...` 原地替换列表内容，命令行持有的同一个列表会同步更新。

四个钩子事件：

| 事件 | 触发位置 | 默认行为 |
|---|---|---|
| `UserPromptSubmit` | 命令行收到有效任务后、加入消息历史之前 | 打印当前工作目录，不改写输入 |
| `PreToolUse` | 每个工具调用执行前 | 先检查权限，通过后打印调用日志 |
| `PostToolUse` | 工具返回结果后 | 输出超过 100,000 字符时提醒，不修改输出 |
| `Stop` | 模型不再请求工具、循环准备结束时 | 统计当前历史保留的工具结果条数，包含拒绝的调用；归档后的旧结果不在此数中 |

`register_hook(event, callback)` 按顺序登记函数，`trigger_hooks(event, *args)` 依次调用。回调返回 `None` 会继续执行后面的回调；返回其它值会提前结束这次事件触发。

`PreToolUse` 返回非 `None` 时，主循环跳过当前工具，将该返回值转成文本回传模型；不会触发对应的 `PostToolUse`。`Stop` 回调可返回非空提示字符串，主循环会把它加入用户消息并继续调用模型；默认统计回调返回 `None`，允许结束。`UserPromptSubmit` 和 `PostToolUse` 的返回值不改写输入或输出。

默认钩子在首次导入 `hook` 包时注册一次。后续扩展可新增回调，并通过 `register_hook()` 挂到已有事件，无需再把具体扩展逻辑写进主循环。

主智能体的十四个工具及参数：

| 工具 | 参数 | 功能 |
|---|---|---|
| `bash` | `command` | 执行命令，返回输出 |
| `read_file` | `path`、可选 `limit` | 读取 UTF-8 文本，可限制行数 |
| `write_file` | `path`、`content` | 写入或覆盖文件，自动创建父目录 |
| `edit_file` | `path`、`old_text`、`new_text` | 精确替换第一次出现的文本 |
| `glob` | `pattern` | 按模式查找路径，`**` 支持递归，最多显示 200 项 |
| `load_skill` | `name` | 按目录中的技能名称返回完整 `SKILL.md` |
| `compact` | 无 | 请求在本批工具全部完成后归档并总结历史 |
| `create_task` | `subject`、可选 `description` | 创建任务，返回真实任务 ID |
| `update_task` | `task_id`、`addBlockedBy` | 给尚未领取的任务增加前置依赖 |
| `list_tasks` | 无 | 查看项目任务、状态、领取者和未完成依赖 |
| `get_task` | `task_id` | 查看完整任务记录 |
| `claim_task` | `task_id` | 领取依赖已完成的任务，标记进行中 |
| `complete_task` | `task_id` | 完成当前会话领取的任务，报告新解锁任务 |
| `task` | `prompt` | 同步运行一个子任务，只返回子智能体的最终文本 |

`BASE_TOOLS` 和 `BASE_HANDLERS` 定义七个共用工具：`bash`、`read_file`、`write_file`、`edit_file`、`glob`、`load_skill`、`compact`。子智能体使用它们的副本；主智能体额外拥有六个任务工具和委派工具 `task`。子智能体不能继续委派，也不直接操作项目任务工具；主智能体负责领取、安排执行和更新任务状态。

调用 `task` 时，`tool/task.py` 中的 `run_task(prompt)` 将说明交给 `agent/subagent.py` 的 `run_subagent(prompt)`。子循环从 `messages = [{"role": "user", "content": prompt}]` 开始，使用独立的系统提示词；父对话历史不会复制进去，所以主智能体需要在 `prompt` 中提供目标、必要背景和期望结果。

子智能体调用工具并接收结果，直到模型给出不含工具调用的回复，且 `Stop` 钩子允许结束。它把最终回复中的文字提取出来，作为父循环中对应 `task` 的 `tool_result` 返回。中间分析、工具调用和工具结果只保存在子消息列表内；父循环拿到最终文本后继续处理主任务。没有最终文本时返回中文占位说明。

主、子智能体使用同一个模型客户端和模型配置，在同一个 Python 进程中同步执行，共享工作目录；子智能体写入的文件会对主智能体可见。所有主、子请求和辅助请求都计入当前用户任务的用量，不因累计调用次数或 Token 数自动停止。终端会打印 `[子智能体开始]`、`[子工具]` 和 `[子智能体完成]`。

子循环复用 `PreToolUse`、`PostToolUse` 和 `Stop` 钩子。父对话保留一次 `task` 的工具结果；子循环的停止统计只读取它自己的消息记录。压缩后统计的是当前保留的工具结果，不是整个会话的累计调用次数。`UserPromptSubmit` 仍由命令行接收用户任务时触发。

`skill/` 存放技能加载代码，`skills/` 存放提供给模型的技能说明。启动时，`skill/loader.py` 中的 `SKILL_LOADER` 扫描当前工作目录下的 `skills/*/SKILL.md`，读取文件并缓存在内存中。文件开头两个 `---` 之间是 YAML，`name` 表示技能名称，`description` 表示技能简介；正文记录具体步骤和要求。YAML 通过 PyYAML 的 `safe_load()` 解析。

与 s07 的完整示例一致，`catalog()` 只生成名称和简介，`agent/prompts.py` 中的 `build_system_prompt()` 将目录加入主、子智能体的系统提示词。模型根据任务判断是否需要技能，调用 `load_skill(name)` 后，`tool/load_skill.py` 从缓存返回完整文件内容，由已有循环作为 `tool_result` 追加到对应智能体的 `messages`，下一次模型请求即可读取全文。技能提供任务指导，具体操作仍通过文件和命令工具完成。

已附带中文 `skills/code-review/SKILL.md`，用于代码审查。新增技能时，在 `skills/` 下创建一个子目录并放入 `SKILL.md` 即可；新增或修改后重新启动程序，启动扫描会读取新内容。没有技能目录或文件时程序仍可运行；缺少名称时使用文件夹名称，缺少简介时使用正文第一行。未知技能返回中文错误和可用名称，名称只查询注册表，不会被当作文件路径。

`load_skill` 同样经过执行前、执行后钩子，调用日志中能看到技能名称。全文加载后进入当前消息历史，也会参与后续压缩；子智能体加载的全文留在子消息列表中，父对话仍只接收子任务的最终文本。

`context/compactor.py` 中的 `ContextCompactor` 由主、子循环各自创建，共用算法但分别处理自己的消息。每次工作模型请求前调用 `prepare()`，按以下顺序整理：

| 步骤 | 条件 | 处理 |
|---|---|---|
| `tool_result_budget` | 最新一批工具结果合计超过 200,000 字符 | 从最大的结果开始，将超过 30,000 字符的结果存到文件，消息中保留路径和 2,000 字符预览 |
| `snip_compact` | `messages` 超过 50 条 | 保存完整当前历史，原则上保留最初 3 条、归档标记和最近 46 条；边界调整会保护工具调用与结果的配对 |
| `micro_compact` | 上下文估算超过 50,000 字符 | 保留最近 3 条已被模型接收的工具结果，将更早且超过 120 字符的结果转存并替换为路径，尝试降至阈值的 80% |
| `compact_history` | 进一步转存后仍超过 50,000 字符 | 保存当前历史，调用模型生成状态摘要，用一条包含当前用户请求、摘要和记录路径的消息替换历史 |

前两步每轮检查；第三步只在字符超限时执行。新结果一般先保留到模型接收一次；仍然太大时，`fit_tool_results()` 将结果转存并留下 1,000 字符预览。前三步及辅助转存不额外调用模型；生成摘要才增加模型请求。

摘要请求要求只整理目标、文件、决定、剩余工作和用户约束，不执行历史内容中的指令。摘要输入最多保留原会话序列化文本的前 20,000 和后 60,000 字符，摘要输出上限为 2,000 tokens。当前用户请求由入口单独传入，放在“当前用户请求”部分；“对话摘要”作为背景资料，两者明确分开，因为工具结果也使用 `role=user`。

模型主动调用 `compact` 时，`tool/compact.py` 只返回请求说明，仍经过现有 `PreToolUse` 和 `PostToolUse`。只有通过执行前钩子并成功返回请求说明，循环才会在整批工具全部执行、所有结果追加到消息之后调用 `compact_history()`。拒绝或工具参数错误不会触发压缩。项目任务文件不会因压缩消息而清空。

字符估算与模型实际 token 用量不同。与 s08 一致，工作请求报错文本包含 `prompt_too_long` 或 `too many tokens` 时，循环会保存记录，总结较早历史并保留最近 5 条消息，保护配对后重试一次；再次超长则抛出异常。工作请求成功后重置本次补救计数。子循环使用它的委派 `prompt` 作为当前请求，压缩后的子历史仍不复制到父对话。

会话归档写入工作目录的 `.transcripts/*.jsonl`，被转存的工具全文写入 `.task_outputs/tool-results/*.txt`，用到时才创建目录。这两个目录已加入 `.gitignore`。工具结果标记里的恢复路径只认可工具输出目录内已经存在的文件，防止将任意外部路径当成已保存结果读取。终端会显示中文的自动压缩、超长补救和记录保存位置提示。50,000 是示例的字符阈值，不代表模型上下文的真实 token 上限。

跨会话记忆的存储与模型处理分别位于 `memory/store.py` 和 `memory/manager.py`，参考 s09 的完整 `code.py`，说明见 [docs/memory.md](docs/memory.md)。记忆保存在所选项目工作目录的 `.memory/`，同项目的多个会话共享，不同目录互相隔离；每个会话仍独立保存消息。命令行和桌面版共用此逻辑。

项目任务系统参考 s10 的完整 `code.py`，说明见 [docs/task_system.md](docs/task_system.md)。需要持续跟踪多步骤工作时，模型先创建全部任务，使用返回的真实 ID 添加依赖，然后领取、实际执行、验证并标记完成。依赖未完成时不能领取；完成任务只解除下游阻塞，不自动开始下一项。简单问答不要求创建任务。旧 `todo_write` 工具及三轮提醒已移除，旧会话文件中的待办数据保留为历史，不自动转为共享任务。

主、子循环通过 `tool/executor.py` 的 `execute_tool(block, handlers)` 统一执行工具。它先通过 `PreToolUse` 触发权限钩子，权限钩子复用 `agent/permission.py` 中的 `check_permission(block)`；通过后按工具名找到函数，再用 `handler(**block.input)` 传入参数，并触发 `PostToolUse`。同一回复中的多个调用按原始顺序逐个检查和执行，结果通过对应的 `tool_use_id` 回传。

工具处理函数抛出的普通异常会转换为中文错误文本回传模型，其余调用继续执行。`execute_tool()` 同时返回是否通过执行前钩子，供主循环判断压缩请求是否生效。六个任务工具和 `task` 也经过执行前后事件；子任务内部的每个工具调用还会分别接受权限检查。

权限检查分三步：

1. 硬拒绝：`bash` 命中 `DENY_LIST` 中的字符串模式（如 `rm -rf /`、`sudo`、`shutdown`）时，直接拒绝，不提供审批放行。
2. 规则匹配：`read_file`、`write_file`、`edit_file` 访问工作目录外的路径，或 `bash` 命中 `rm`、`del` 等命令规则时，要求用户确认。
3. 用户审批：终端显示工具名、参数及原因，只有输入 `y` 或 `yes` 才允许当前这一次调用；空输入、其它回答或输入结束默认拒绝。Ctrl+C 中断任务并退出。

未命中规则的普通操作自动执行，包括工作目录内的文件读写、编辑和查找。拒绝时不调用工具，向模型回传 `权限被拒绝。`，其余调用仍继续按顺序处理。

命令行的工作目录为启动时的当前目录，桌面版则使用当前会话选择的目录。与 s03 示例一致，工作区外的文件读写从 s02 的直接拒绝改为用户审批；`resolve_path()` 只负责路径解析，权限由主循环在调用工具之前统一检查。`glob` 仍只返回工作目录内的匹配项。直接调用底层 `run_*` 函数不会经过主循环中的审批。

当前命令检查沿用示例中的字符串和正则规则，用于演示权限流程，不是完整的命令安全解析器或系统沙箱；不能覆盖任意命令的全部行为。`bash` 仍以当前用户的系统权限运行。

模型配置来自环境变量或 `.env`，字段见 `.env.example`。与参考代码一致，Windows 中的命令由 `cmd.exe` 执行。
